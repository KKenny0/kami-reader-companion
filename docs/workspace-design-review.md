# Kami 工作空间设计收敛

日期：2026-09-26。Q1–Q10 已由用户逐轮确认，用户已确认整体理解并结束访谈。本文记录已确认设计，不代表已经实施、验证或获准发布。

## 目标与依据

Kami Reader 提供可独立使用的视觉基础，Companion 保留完整沉浸工作空间定位。以阅读、编辑、查阅和多文档对照的日常效率为最终标准，保留 One Field 的连续外壳，不增加新的产品或模式。

术语见 [CONTEXT.md](../CONTEXT.md)。边界决策见 [ADR 0001](adr/0001-workspace-purpose-and-user-preferences.md) 和 [ADR 0002](adr/0002-stable-documents-and-window-focus.md)。这些新决策修订旧交接文档中的冲突条款，不修改历史交接原文，也不把历史截图当作新实现的验收证据。

## 已确认的体验

| 范围 | 决策 |
| --- | --- |
| 设置 | 普通模式和 Stage 都尊重用户显式设置的字体、正文宽度、背景和强调色。宽度是上限，受 pane 可用空间约束。 |
| 文档稳定性 | 所有 Markdown pane 保持稳定排版；点击另一 pane 不改变原文档的字号、宽度、间距和换行。阅读／编辑的必要差异保留。 |
| 内容语义 | 普通模式和 Stage 均取消自动导语、READING NOTE 和修改日期装饰；文件名和正文 H1 保留原生关系。 |
| Focus | 每个窗口内的临时工作状态，跟随 Markdown 文件、pane 和阅读／编辑切换；非 Markdown 视图暂停强调，返回后恢复。明确关闭、Escape 或重启结束。 |
| 参考文档 | 取消非活动 pane 的整体透明度降低；当前文档的 Focus 强调也必须保持周边文字可读。 |
| Stage 与白纸预览 | 继续绑定当前文档，不转移到新文档。白纸预览是显式请求的临时白纸配色，不是 PDF 分页预览。 |
| 模式入口 | 保留现有命令，在现有文档菜单集中提供三个带选中状态的入口；开启后提供简短、可操作的状态提示和直接退出能力。不新增 Ribbon 按钮或默认快捷键。 |
| Escape | 菜单和弹窗优先处理；文档层先退出 Stage，再退出 Focus。白纸预览沿用其命令及直接退出入口，不增加 Escape 层级。 |
| 窄 pane | 根据 pane 实际空间收缩装饰性留白和标题尺度，保留用户正文字号；不自动关闭侧栏或合并 pane。 |
| 宽内容 | 优先利用所在 pane 的剩余空间，不足时局部横向滚动，不挤宽整个工作区。 |

## 实施边界

两个仓库一起核对设置继承与窄 pane 排版，主要涉及主题的 `theme.css`，Companion 的 `styles.css`、`src/reading-presence.ts`、`src/main.ts` 及必要的现有测试。具体改动以实际调用路径为准，本文不是已经验证的逐文件实施计划。

复用现有模式和生命周期处理，不增加共享包、新服务、文章 frontmatter 协议、设置面板或持久化模式偏好。不改写笔记内容。保留 Outline 无法可靠映射时的原生回退。

性能审查已发现滚动调度会连带刷新宽内容测量；这是实施时需要测量和验证的技术风险，尚未证实实际卡顿。优先检查能否让滚动只刷新定位，让内容或尺寸变化触发宽内容测量，不预先引入缓存框架。

## 验收

macOS 和 Windows 均需当前版本的真实 Obsidian 关键流程验收，分别覆盖 Default 与 Kami Reader，包含浅色和深色。Linux 标明未实机验收；Companion 继续仅支持桌面。

1. 设置继承：改变字体、宽度、背景和强调色，普通模式与 Stage 均保持选择；白纸预览退出后恢复原配色。
2. 排版稳定：双 pane 反复切换活动焦点，原文档的换行、标题位置和阅读位置不因焦点变化而重排。
3. 密度：中文长文、任务列表、属性密集笔记，以及宽窗口中的窄 pane 都可正常读写；正文不被迫缩小或造成工作区横向溢出。
4. 生命周期：Focus 跨文档和阅读／编辑继续生效，进入非 Markdown 视图暂停、返回恢复；窗口间互不迁移，关闭和卸载清理状态。
5. 入口与退出：命令与菜单状态一致，状态提示可由键盘操作；菜单／弹窗优先处理 Escape，Stage 与 Focus 按顺序退出。
6. 内容：取消自动文章装饰，参考 pane 保持正常可读；宽表格、代码、图片的局部滚动不影响整个工作区。
7. 性能：真实长文与多 pane 持续滚动，检查宽内容测量次数与主线程耗时，报告实测结果，不以静态源码或单元测试代替流畅度结论。

本次访谈前 Companion 的 58 项测试通过；主题测试因缺少本地 `yaml` 依赖未能运行。这些是修改前的基线信息，不是新设计的验收结果。没有 Windows 环境时可完成开发，但跨平台验收必须保持未完成状态。
