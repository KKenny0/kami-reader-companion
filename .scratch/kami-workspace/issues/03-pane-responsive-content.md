# 03: 窄 pane 保持读写密度，宽内容局部展开

**What to build:** 宽窗口里的窄文档区域也能舒适读写：优先收缩装饰性留白与标题尺度，宽内容只使用所在 pane 的可用空间。

**Blocked by:** 01：切换 pane 时保持文档排版与语义稳定、02：主题设置在 Companion 与 Stage 中持续生效

**Status:** done

**范围与工作量：** 两个仓库，中等；复用现有宽内容处理。

- [x] 在宽窗口打开双侧栏和双 pane，分别改变 pane 宽度，布局响应 pane 空间而非仅响应窗口宽度。
- [x] 正文字号保留用户设置，不自动关闭侧栏、合并 pane 或产生工作区横向溢出；One Field 沟槽仍可辨识和操作。
- [x] 中文长文、任务列表、属性密集笔记与长标题均能正常读写。
- [x] 宽表格、代码、图片、图表和嵌入优先使用 pane 剩余宽度，仍超宽时在局部滚动；嵌套列表和 callout 中的内容不越界。
- [x] 媒体延迟加载、拖动 pane 尺寸、Stage 进入和退出后重新适配，无残留宽度或滚动位置异常。
- [x] 保留宽内容计算的边界测试，并提供窄 pane 与宽内容真实应用证据。

本地实施与 macOS 复审完成；证据见 [第二轮复审报告](../../../docs/workspace-phase2-review.md)。双平台正式候选验收留在 07。
